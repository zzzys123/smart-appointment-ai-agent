# 知识库生命周期、健康检查与观测面板

本阶段不依赖 Redis 或 Docker，也不修改冻结的 Golden v2。目标是让 90 条本地知识基线可核对、
可增量同步、可备份回滚，并把系统健康和已有 RAG 观测事件展示在管理页面。

## 知识库基线

`knowledge_documents/MANIFEST.json` 固定 10 篇受管文档的文件 SHA-256、来源编号和 80 个分块哈希。
SQLite 当前 90 条活跃知识由 80 个受管分块和 10 条早期默认知识组成；状态报告会分别展示，
不会把未受管的 10 条误判为文档漂移。

常用命令：

```powershell
# 只读校验，不调用 Embedding API
.venv\Scripts\python.exe scripts\manage_knowledge.py status

# 预览重新生成的清单；加 --write 才覆盖清单文件
.venv\Scripts\python.exe scripts\manage_knowledge.py manifest
.venv\Scripts\python.exe scripts\manage_knowledge.py manifest --write

# 同步默认只预览；--apply 会先创建 SQLite 快照，再增量同步并按需重建索引
.venv\Scripts\python.exe scripts\manage_knowledge.py sync
.venv\Scripts\python.exe scripts\manage_knowledge.py sync --apply

# 单独备份和重建索引
.venv\Scripts\python.exe scripts\manage_knowledge.py backup
.venv\Scripts\python.exe scripts\manage_knowledge.py rebuild-index

# 回滚只接受 data/backups/knowledge 下的快照，并要求显式确认；回滚前还会再保存当前库
.venv\Scripts\python.exe scripts\manage_knowledge.py restore `
  data\backups\knowledge\knowledge-YYYYMMDDTHHMMSSZ.db --confirm-restore
```

管理页的“备份并同步”执行相同保护流程。网页不提供回滚按钮，避免浏览器误操作覆盖 SQLite。

## 健康检查

- `GET /health`：轻量存活检查，不依赖数据库或模型。
- `GET /api/system/health`：数据库、活跃知识、内存索引、模型配置、Redis 和观测目录详情。
- 模型检查只检查供应商、模型名和密钥是否已配置，不发送外部 API 请求，也不会产生费用。
- Redis 是可选组件；未安装或 `REDIS_ENABLED=false` 时显示 `disabled`，单机服务仍可处于 `ok`。

响应永远不会返回 API Key，只返回 `key_configured: true/false`。

## 观测面板

构建前端后访问 `/ui/observability`。页面每 30 秒读取：

- `GET /api/system/health`
- `GET /api/system/metrics`

页面展示检索 P95、拒答率、错误率、重排触发/回退率、Provider Token、调用失败率、费用覆盖率和
估算费用。它只聚合隐私安全 JSONL，不读取原始问题、Prompt、回答或 Session ID。

事件少于 30 条时页面会明确提示：数据只能用于验证观测链路，不应据此调整检索阈值。
